# 同一性

run の同一性は，誰がどう名付けたかではなく，それが実際に何であったかから計算される．要点はそこにある．そうして初めて，リポジトリをまたいでも年をまたいでも，2 つのディレクトリを機械が比較できる．

## 2 つの識別子

- **`run_uid`** —— ULID．時刻順にソートされ，マシンをまたいで一意で，すべての join の鍵になる．
- **`run_slug`** —— ディレクトリ名．`<subcommand>_<timestamp>_<cfg8>_<exec4>` の形で，`config_hash` の先頭 8 桁と `execution_hash` の先頭 4 桁（いずれも 16 進）を含む．人間のためのもので，**一意ではない**．衝突したときは `-N` の接尾辞が付く．

slug がハッシュの接頭辞を持つため，ディレクトリ名とメタデータを突き合わせて検査できる．実際に検査している —— [検査](checks.ja.md) を参照．

## 3 つのハッシュ

いずれも BLAKE3 で，16 進で出力される．各ハッシュは入力の **長さ前置き連結** に対して計算されるので，入力の中身によって入力列が曖昧になることはない．欠けている項目は長さ 0 の入力に潰れる．入力そのものが *落ちる* ことは決してないので，「存在しない」と「空」は区別され続ける．

### `env_hash` —— 5 入力

`os`，`arch`，`rustc_version`，`python_version`，そして lock ファイル群（各 lock が kind・file・ハッシュアルゴリズム・ハッシュ値を寄与し，kind と file でソートされる）．

`host` は意図的に入力に **含めない**．マシン名は記録するが，他が同一な 2 台のマシンが 2 つの異なる環境を生んではならない．

### `config_hash` —— 条件とデータ

`config.parameters` を取り，制御ブロックが除外するポインタ —— `hash_exclude`，`seed_pointers`，`determinism.invariant_to` をまとめて —— を刈り取り，残りを正規化し，使用した全データセットの同一性と一緒にハッシュする．

ここで seed が刈られることが，複製を複製たらしめている．条件を共有するので `config_hash` を共有し，`execution_hash` だけが異なる．

各データセットは 10 個の入力を寄与する —— `role`，`name`，`dataset_id`，`version`，`split`，ハッシュアルゴリズム，ハッシュ値，`hash_scope`，`uri`，`n` —— 順序は `(role, name)`．これにより `config_hash` は「同じパラメータファイル」ではなく「同じデータに対する同じ実験条件」を意味するようになる．

### `execution_hash` —— 6 入力

`config_hash`，seed 群，`git_commit`，作業ツリーが dirty だったか，その差分のハッシュ，そして `env_hash`．

seed は `seed_pointers` の各ポインタを `parameters` に対して解決して集める．ポインタをソートした順に，ポインタ自身と，それが解決した値の正規化形を寄与する．`code` ブロックが全く無い場合，その 3 入力は消えるのではなく長さ 0 の入力として残る．

*この全く同じものは既に実行済みか* に答えるのがこのハッシュである．同じ条件，同じ seed，同じ commit，同じ環境．

## 正規化

正規化形は，2 つの実装がハッシュで一致する前に一致していなければならないものである．固定するのは：

- キーの順序
- Unicode 正規化（NFC）
- 文字列のエスケープ
- 浮動小数点の書式
- 欠損と `null` の区別

`schema/v1/testvectors/canonicalize.json` と `length_prefix.json` がこれらを固定し，`hashes.json` が 3 つのハッシュを —— データ無し・コード無し・lock 無しといった退化ケースも含めて —— 固定する．すべての実装は，入力だけから各ケースの **すべての** フィールドを再現できなければならない．中間の `canonical` / `joined` フィールドがあるのは，不一致が「ハッシュが違う」だけでなく *どこで* 分岐したかを示すためである．[スキーマ](schemas.ja.md) を参照．

## ハッシュで何ができるか

| 問い | 答え方 |
| --- | --- |
| 同じ条件か | `config_hash` が同じ |
| その複製か | `config_hash` が同じで `execution_hash` が異なる |
| この全く同じものは既に実行済みか | `execution_hash` が同じ |
| 足元で環境が変わったか | `config_hash` が同じで `env_hash` が異なる |

コマンドラインでは `runvault path --config-hash …` と `runvault path --execution-hash … --finished` に対応する．[コマンドライン](cli.ja.md) を参照．
