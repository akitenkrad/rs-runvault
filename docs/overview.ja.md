# 概要

## 何が問題か

研究の結果は，それが得られた条件と同じだけの価値しか持たない．そしてその条件はたいてい散らばっている．パラメータファイルはここ，乱数 seed はコマンドライン引数，ツールチェインはたまたまそのマシンに入っていたもの，データセットは後から作り直されたもの．半年経つと，似た名前の 2 つのディレクトリが同じ実験なのか別の実験なのか，誰にも言えなくなる．

`runvault` は *条件と結果を一緒に*，固定された 1 つの形で記録する．異なるリポジトリ・異なる分野・異なる年に得られた run を，比較し，保全し，引用できるようにするためである．

## 1 回の実行が 1 つのディレクトリ

1 回の実行が 1 つのディレクトリを作り，そのディレクトリが記録そのものになる．条件（`config.json`），メタデータと来歴（`run.json`），数値（`metrics.csv`），観測（`events.jsonl`），結末（`status.json`），そして run が書いたすべてのファイルの同一性（`manifest.csv`）がそこに入る．全体像は [run ディレクトリ](run-directory.ja.md) を参照．

その上の層 —— `runvault query` の背後にある DuckDB インデックス，`runvault report` が出すダッシュボード用ペイロード，その他のトラッキング UI —— はすべて派生物である．削除してもディレクトリから再構築できるし，実験コードが依存するのは `runvault` だけでよい．

## 同一性は 3 つのハッシュ

runvault の中心的な考え方は，run の同一性を *名前で付けず，計算する* ことにある．

| ハッシュ | 何から計算するか | 何に答えるか |
| --- | --- | --- |
| `env_hash` | os，arch，`rustc` のバージョン，Python のバージョン，lock ファイル群 | 同じマシン・同じツールチェインだったか |
| `config_hash` | 無関係と宣言された部分を取り除いた実験条件と，使用した全データセットの同一性 | 同じ条件か |
| `execution_hash` | `config_hash`，seed，git commit，作業ツリーが dirty だったかとその差分のハッシュ，`env_hash` | この全く同じものは既に実行済みか |

正規化された入力に対するハッシュなので，「同じ条件」「同じ実行の繰り返し」が，2 人の人間が同じ命名をしたかどうかではなく機械の判定になる．同一条件の複製（replicate）は `config_hash` を共有し `execution_hash` だけが異なる．何も変えない再実行は両方を再現する．規則は [同一性](identity.ja.md) にあり，入力の詳細は実装間テストベクタで固定されている．第 2 実装は，一致するか，あるいは証明可能な形で誤っているかのどちらかになる．

## リポジトリの中身

| パス | 内容 |
| --- | --- |
| `schema/v1/` | 凍結された JSON Schema，平坦化インデックスの列定義，コア語彙．**これらのファイルが仕様である．** |
| `schema/v1/testvectors/` | 正規化とハッシュのベクタ．2 つの実装が一致することを示すためのもの． |
| `crates/runvault/` | Rust のリファレンス実装．run を書くために依存してもデータベースは入らない． |
| `crates/runvault-cli/` | `runvault` バイナリと，`query` の背後にある DuckDB インデックス． |
| `python/` | Python の第 2 実装．同一性・writer・読み出し側． |
| `tools/` | スキーマ・モデル・ベクタの整合を保つバリデータとジェネレータ． |

crate が 2 つあるのは意図的である．ライブラリは再現リポジトリ群が run を *書く* ために依存するものであり，そのためにデータベースをコンパイルさせるわけにはいかない．DuckDB インデックスはバイナリ crate 側に置いてある．[Rust](rust.ja.md) を参照．

## 現状

`schema/v1` は凍結済みで，Rust ライブラリ，コマンドライン（`sync`・DuckDB インデックス・ダッシュボード用ペイロードを含む），Python パッケージのいずれも実在し，CI で動かされている．バージョンは `0.1.0`．形は固まっており，周辺のツールがまだ育っている段階である．

既知の制約が 1 つある．`crates/runvault` は `schema/v1/vocabulary.toml` を自分のディレクトリの外から `include_str!` で読むため，現状のままでは crates.io に publish できない．これが問題になるのは publish するときだけで，publish の予定はまだない．
